# Приклад для мосту HTML → DOM → fetch → DevTools

Це незалежний локальний стенд для матеріалу
Міст HTML → DOM → fetch → DevTools (див. методичні рекомендації).
Він містить одну HTML-сторінку, мінімальний CSS, невеликий JavaScript-обробник і
локальний endpoint `POST /api/greetings`. База даних, Docker, автентифікація та
код студентського варіанта не потрібні. Перевірений тег стартового репозиторію
курсу — `starter-v0.1.0` (commit `4aa18b3`).

## Передумови

- .NET SDK `10.0.302` або новіший patch того самого feature band `10.0.3xx`;
- сучасний браузер із DevTools;
- термінал.

Файл `global.json` задає мінімальну версію SDK `10.0.302` і політику
`latestPatch`. Тому буде використано `10.0.302` або новіший установлений patch
того самого feature band `10.0.3xx`, але не інший feature band. Якщо сумісного
SDK немає, встановіть указану версію; не змінюйте `global.json` навмання. Якщо
інструментарій C# ще не встановлено, спершу опрацюйте
Міст 1 (див. методичні рекомендації).

## Відновлення та складання

У цій директорії виконайте:

```bash
dotnet restore
dotnet build --no-restore
```

Ці команди однакові в macOS, Linux і Windows PowerShell.

## Запуск

Запустіть локальний застосунок на фіксованій адресі:

```bash
dotnet run --no-build --urls http://127.0.0.1:5078
```

Не закриваючи процес, відкрийте в браузері
`http://127.0.0.1:5078/`. Уведіть ім’я та натисніть «Надіслати».

Якщо порт `5078` уже зайнятий, у параметрі `--urls` укажіть інший вільний порт
і відкрийте в браузері адресу з тим самим номером. Наприклад, після
`--urls http://127.0.0.1:5079` відкривайте `http://127.0.0.1:5079/`.

## Що перевірити в браузері

1. До натискання кнопки відкрийте DevTools клавішею `F12` або поєднанням
   `Ctrl+Shift+I` у Windows і Linux, `Cmd+Option+I` у macOS чи через меню
   інструментів розробника. У Safari спершу ввімкніть функції для
   веброзробників у параметрах Safari. Перейдіть на вкладку Network.
2. Відкрийте `http://127.0.0.1:5078/?demo=1`, використавши фактичний номер порту
   застосунку. Знайдіть запис із URL сторінки й типом `Document`, `Doc` або
   `HTML`. Порівняйте `query parameters` у URL з відсутнім `request body`.
3. Надішліть форму зі звичайним ім’ям та знайдіть запис `greetings` із method
   `POST`. За потреби використайте фільтр `Fetch/XHR` у Chrome або Edge чи
   `XHR` у Firefox. Фільтр приховує запис документа, тому перед повторенням
   кроку 2 його потрібно вимкнути.
4. На боці запиту перевірте URL, header `Content-Type` і JSON у `request body`;
   на боці відповіді — status code, headers і JSON у `response body`.
5. Зіставте цей запис із викликом `fetch` у `wwwroot/app.js`.
6. Переконайтеся, що відповідь з’явилася в абзаці та додалася до списку.
7. Надішліть порожнє поле й одразу подивіться на нього: браузер має показати
   власну підказку. Після цього перевірте Network: попередній результат не має
   змінитися, а нового запису `POST` не буде. Текст підказки залежить від мови
   браузера.
8. Надішліть один пробіл. Запит має вийти, API має повернути status code `400`,
   а сторінка — показати `Помилка 400: Уведіть ім’я.`
9. Уведіть `<b>Олена</b>` і надішліть форму. Сторінка має показати символи
   `<b>` як звичайний текст, а не зробити ім’я жирним.

Для необов’язкового незалежного виклику endpoint у bash можна використати:

```bash
curl -i -X POST http://127.0.0.1:5078/api/greetings \
  -H 'Content-Type: application/json' \
  -d '{"name":"Олена"}'
```

Якщо під час запуску вибрано інший порт, замініть `5078` у команді. У PowerShell
той самий необов’язковий виклик має такий вигляд:

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:5078/api/greetings `
  -ContentType 'application/json' `
  -Body '{"name":"Олена"}'
```

## Безпечна мінімальна зміна

У функції `showGreeting` файла `wwwroot/app.js` знайдіть підпис
`Відповідь API:` і замініть його на `Перевірено у браузері:`. Оновіть сторінку,
повторно надішліть форму й перевірте новий текст. Значення, одержане від API,
як і раніше передається властивості `textContent`.

Якщо новий підпис не з’явився, виконайте примусове перезавантаження сторінки або
тимчасово вимкніть кеш у вже відкритій панелі Network, а потім повторіть дію.

## Очікуваний навчальний результат

Після роботи з прикладом студент уміє:

- пояснити, коли виконується обробник `submit`;
- прочитати готовий `fetch` і назвати method, URL, headers та body;
- знайти відповідні HTTP-запит і HTTP-відповідь у DevTools Network;
- відрізнити request body від query parameters, а response body — від headers;
- змінити звичайний текст через `textContent`;
- додати елемент списку через `createElement` і `append` на рівні читання коду.

Приклад не навчає створювати клієнтську частину або API з нуля. Він також не
замінює наскрізний маршрут до PostgreSQL, індивідуальну зміну та докази з ЛР 1.
