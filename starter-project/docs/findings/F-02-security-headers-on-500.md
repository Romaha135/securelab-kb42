# F-02. Заголовки безпеки зникають на відповіді 500

**Статус:** ЗАПОВНИТИ (Fixed / Temporarily accepted)
**Актив:** передбачувані заголовки браузерної безпеки на всіх класах відповідей
**Компонент:** порядок middleware у Program.cs (headers vs UseExceptionHandler)
**Пріоритет:** ЗАПОВНИТИ (P1 / P2 / P3)

## Передумови і межі огляду
Commit ЗАПОВНИТИ; профіль; акаунти; reset-команда; маршрути; виключення.

## Відтворення
1. Production-like запуск з недосяжною БД (порт 54399). 2. POST /api/auth/login з вигаданим паролем. 3. curl.exe -i: перевірити X-Content-Type-Options, Referrer-Policy, Content-Security-Policy на 500. ЗАПОВНИТИ фактичні заголовки. УВАГА: якщо заголовки НА 500 Є, F-02 не існує: використай F-03 (лог).

## Вплив і ймовірність
**Статус перевірки:** ЗАПОВНИТИ (спостережено локально / оцінено за кодом)
ЗАПОВНИТИ. CVSS не вигадувати.

## Першопричина
Middleware заголовків стоїть після UseExceptionHandler і ставить заголовки до next; exception middleware очищає відповідь. ПІДТВЕРДИТИ власним спостереженням.

## Виправлення
Middleware перенесено перед UseExceptionHandler, заголовки ставляться в Response.OnStarting. Commit ЗАПОВНИТИ.

ЗАПОВНИТИ: ті самі кроки на fixed commit, фактичні статуси.

## Positive regression
Звичайні відповіді (/, API 200, 400, 404) мають ті самі заголовки; /scalar у Development без CSP як раніше.
